# Дополнительные функции

## Пользовательские категории

Система пользовательских категорий предназначена для настройки и расширения списка категорий задач в рамках темы. Пользователь может добавлять собственные категории, изменять существующие, а также импортировать и экспортировать категории в виде JSON-файла.

### Общая модель

- Все изменения выполняются в **черновике категорий**.
- Черновик может содержать временно невалидные данные.
- Сохранение в тему возможно **только при отсутствии ошибок**.
- Базовые категории всегда присутствуют и не могут быть удалены, но могут быть переопределены.

---

### Базовые категории

- Базовые категории загружаются из темы автоматически.
- Они помечены как `isBase`.
- Базовую категорию нельзя удалить, но можно:
  - изменить её название;
  - изменить связанный пресет;
  - сбросить к исходному состоянию темы.

---

### Добавление и редактирование категорий

Пользователь может:

- добавлять новые категории;
- редактировать существующие;
- удалять пользовательские категории.

#### Ограничения и валидация

Для каждой категории действуют правила:

- название категории не может быть пустым;
- названия категорий должны быть уникальны (без учёта регистра);
- категория должна быть привязана к существующему пресету оформления.

Валидация выполняется:

- при редактировании категории;
- при подтверждении изменений;
- перед сохранением всей темы.

---

### Импорт категорий

Поддерживается импорт категорий из JSON-файла.

#### Поведение при импорте

- Все текущие пользовательские категории заменяются импортированными.
- Базовые категории:
  - всегда добавляются в черновик;
  - могут быть переопределены импортированными категориями с совпадающим названием.

- При импорте выполняется автоматическая проверка:
  - корректности структуры файла;
  - наличия названий категорий;
  - дубликатов названий;
  - существования указанных пресетов.

Если категория содержит ошибку:

- она добавляется в черновик с пометкой ошибки `hasError`;
- пользователь обязан исправить её вручную перед сохранением темы.

---

### Ошибки и состояние `hasError`

Если категория нарушает правила, она помечается как требующая внимания:

- категория подсвечивается в списке;
- сохранение темы блокируется;
- пользователь видит сообщение с количеством проблемных категорий.

Важно:

- ошибка **не снимается автоматически**;
- категория считается исправленной только после того, как пользователь:
  - открыл её в редакторе;
  - убедился, что форма валидна;
  - подтвердил состояние (явно или неявно).

Это гарантирует, что пользователь осознанно проверил данные.

---

### Экспорт категорий

Пользователь может экспортировать текущие категории в JSON-файл.

- Экспортируются только валидные пользовательские данные.
- В файл не попадают служебные поля (`hasError`, `isBase` и т.п.).
- Экспортированный файл может быть использован для повторного импорта.

---

### Сохранение темы

- Кнопка сохранения недоступна, если в черновике есть категории с ошибками.
- При попытке сохранить тему выполняется финальная проверка.
- В тему никогда не попадают невалидные категории.

---

### Принципы UX

- Пользователь всегда видит, **что именно требует исправления**.
- Ошибки не исчезают без подтверждения пользователя.
- Невозможно случайно сохранить некорректные данные.
- Все действия обратимы до момента сохранения темы.
